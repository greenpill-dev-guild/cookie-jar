# Test-driven development

TDD is the red-green loop. This skill makes the loop produce tests worth keeping: where tests go
in this repo, what a good one looks like, and the rules of the loop. Read `.claude/rules/testing.md`
first; it holds the commands and the runner caveat (`bun run test`, never `bun test`).

## Seams in this repo

A seam is the public boundary you test at. Agree the seams with the user before writing a test.

| Layer | Seam | How |
| --- | --- | --- |
| Pure helpers (`client/lib/**`) | exported function | plain vitest, no mocks |
| Jar hooks (`client/hooks/jar/**`) | the hook through `renderHook` | `vi.mock("wagmi")` returning the reads the hook makes; mock `@/config/deployments.auto` and `@/generated` |
| Result parsers | the exported parser (`parseJarConfigResults`) | feed the batched-read array, assert the config |
| Components (`client/components/**`) | rendered output by role and label | Testing Library; no snapshot tests |
| Contracts (`contracts/src/**`) | external functions on a locally deployed factory and jar | Foundry, `test_`, `test_RevertWhen_`, `testFuzz_` |
| Scripts (`contracts/script/**`) | the struct-taking entry (`planFrom`), one env test | Foundry with `vm.setEnv` in a single test |
| Flows | Playwright against `bun dev` | unauthenticated assertions on copy and roles |

See [tests.md](tests.md) for examples and [mocking.md](mocking.md) for what to mock.

## What a good test is

It reads like a specification of behaviour at the seam ("a hat wearer with balance 1 is eligible")
and survives refactors of the internals. The expected value comes from an independent source
(the contract, a worked example, the plan), never from running the implementation.

## Anti-patterns

- Implementation-coupled: mocking internal collaborators, asserting on Tailwind classes, reading
  private state.
- Tautological: `expect(parse(x)).toEqual(parse(x))`, or a snapshot generated by the code itself.
- Horizontal slicing: writing all tests first, then all code. Work in vertical slices, one test,
  one minimal implementation, repeat.
- Environment leakage in Foundry: `vm.setEnv` is process-global and tests run in parallel.

## Rules of the loop

1. Red before green: watch the test fail for the right reason.
2. One slice at a time: one seam, one test, the smallest code that passes.
3. Refactor only when green, and re-run the file after every refactor.
4. Finish with the full relevant suite: `cd client && bun run test` or `bun run test:contracts`.
